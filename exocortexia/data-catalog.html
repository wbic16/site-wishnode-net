Open Data Catalog

A data-governance catalog: definitions, provenance, and staleness you can check

What it does

Eight synthetic Nebraska datasets, catalogued the way a data-governance program needs them: who owns each dataset, how often it should refresh, where its fields come from, and whether it is current.

  • Field-level definitions. Every field carries a plain definition, a type, and a provenance — where the field's values actually come from.
  • Staleness computed on view. A dataset is STALE when today minus its last-updated date exceeds its declared cadence, FRESH otherwise. The badge is computed the day you look, never stored — a stored badge would itself go stale.
  • Link checks, on demand only. Checking a source link opens a connection and reads the status; checks run only when the link-check endpoint is called, never on page load, so simply viewing the catalog does no network work. Plain http:// links are checked; https:// links are honestly reported as "not checked in demo" rather than silently skipped or faked.

An honest caveat

This is the one application in the suite whose underlying need is an unvalidated hypothesis: we believe a field-level catalog with computed staleness would help a state data program, but no agency has yet confirmed that need with us. Its framing sheet in the repository says so plainly, and so does this page. It is included because the pattern — definitions, provenance, cadence, freshness — is the same discipline the other four apps apply to their own domains.
