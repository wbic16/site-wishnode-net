Security

Security audit and penetration testing for the Exocortexia suite

⏳ Audit results pending

This slot is reserved for the results of the Exocortexia security audit and penetration-testing pass, which is a separate work item currently in progress.

No findings are published here yet, and none should be inferred from this page's existence. When the audit completes, its report will be published in the repository as docs/SECURITY.md and summarized in this slot — including anything it finds, favourable or not.

Until then, the suite's verifiable security-relevant properties are the ones in its test record: hash-chained audit logs with a tamper negative control, redaction-never-mutates originals, SSO assertion replay and tamper rejection, and enumerated rejection of illegal state transitions. See docs/VERIFICATION.md.

Reporting a problem

Exocortexia is a public proof of concept running synthetic data; it holds no production data and is not a deployed state system. If you find a security issue in the code, please open an issue in the Exocortexia repository.
