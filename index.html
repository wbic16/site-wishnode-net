Exocortexia by Phext, Inc.
Records Desk Minutes Publisher Contract Ledger Data Catalog Forms Router Security

Open software for state government, built in the open.

Exocortexia is a proof-of-concept suite of five public-records and transparency applications for states with fewer than 5 million residents — designed against Nebraska statute, written in Rust, and published with its test and load receipts attached.

What it is

The five applications share one storage core. Every document lives as a scroll in a phext — a plain-text, multi-dimensional document store. Every change is written to a hash-chained audit log, and redactions are first-class, reviewable data rather than edits to the original record.

The suite is a single Rust workspace using only the standard library for HTTP — no web framework, no async runtime — so it builds fast, runs on modest hardware, and can be read end-to-end by one person. Sign-in is shared with edit.phext.io through a small HMAC assertion protocol; where SSO is not configured, the apps run in an open demo mode with a visible banner saying so.

Exocortexia is a demonstration of capability, developed in public under the MIT license by Phext, Inc. It is not a deployed state system, and nothing on this site should be read as a claim that it is.

The five applications

Records Desk

Public-records search with audited, reversible redactions and an export packet whose time-and-cost worksheet is explicit arithmetic.

Neb. Rev. Stat. § 84-712 et seq.

Minutes Publisher

Public-meeting agenda and minutes posting with statutory timeliness checks and a hash-chained proof-of-posting log.

Open Meetings Act, §§ 84-1408–84-1414

Contract & Grant Ledger

A contract ledger reconciled against the public State Contracts Database — amendment overlays, expiry alerts, missing-upload flags.

Neb. Rev. Stat. § 84-602.04

Open Data Catalog

A data-governance catalog: datasets with field-level definitions, provenance, refresh cadence, and staleness computed on the day you look.

Framing sheet in the repo docs

Forms Intake Router

Forms intake with a strict, explicit state machine and a no-PII design — routing needs no name, email, or contact field, so the form never asks.

State-machine sheet in the repo docs

The suite ships with its receipts. Full record: docs/VERIFICATION.md in the repository.

Seed corporaDeterministic — regenerating produces identical SHA-256 hashes

The failure we found and fixed: at 500 concurrent connections, the first build failed its latency budget — p95 of 1,048 ms, caused by the standard listener's 128-deep connection backlog. Moving to a 1024-deep backlog brought p95 to 26 ms and p99 to 38 ms with zero errors. The failure, the diagnosis, and the fix are all recorded in the verification document — that record is the point of the exercise.

Honest limits: load numbers are single-node loopback measurements on a 16-core machine — headroom evidence for a small state's traffic shape, not internet latency. The Records Desk demo process carries a 400-document corpus; the 100,000-document figures are proven at the store level.
